## Feature scope still missing for “Strava and more”

Use `docs/FEATURE-COVERAGE.md` as the main ordered backlog, with acceptance criteria. Core concrete gaps identified by source inventory:

1. **Finish recording and identity confidence:** resolve protected key access, pass signup→record→save→detail plus pause/recovery, route CRUD persistence and navigation flows; then physical GPS-under-lock/battery/permission testing; Android counterpart; hosted backend isolation/deletion tests.
2. **Activity management and portability:** edit activity title/notes/RPE and metadata with reprocessing/revision safety; delete/tombstone across personal/social/media stores; manual activity entry; indexed/paged large history; bounded GPX/FIT/TCX import/export and account archive. Validate malformed/oversized files, duplicate handling, timezone boundaries and privacy redaction.
3. **Real segments:** server-side geometry matching and verified effort production (direction, GPS gaps/quality, pauses, privacy zones, simulated activity exclusion, idempotence, provenance, anti-abuse/review/appeal). Client must not be able to set verification. Current leaderboard UI reads already-verified effort rows; no worker produces them automatically.
4. **Real clubs/leagues/challenges:** persistent league enrollment, periods, group scope and scoring/recompute jobs; club detail/feed, roles, invites and events; challenge publishing and scoring. Existing join screens/demo ranking are not a functioning competitive league system.
5. **Ghost racing:** route-position/time matched comparisons against a prior effort, a friend or a segment target. Current ghost uses target activity average pace, not a position-aligned race.
6. **Routes/maps:** run/bike route finding already exists. Add route discovery/recommendations, turn-by-turn/navigation, zoom-aware privacy-preserving heatmap density, offline tile region management/caching, downloaded route packs, network/cache error states. Current heatmap is a route overlay, not a density heatmap; current routing is OSRM-backed, and provider body-read timeout may need hardening.
7. **Devices and sports:** validate HealthKit/Health Connect on physical devices; add watch companion/live BLE HR/power/cadence sensors and FIT/GPX imports/third-party connectors. Recording currently supports run, ride, walk and hike; broaden sports deliberately with sport-specific metrics and UI, not superficial labels.
8. **Training/coaching:** structured plans, adaptive weekly prescriptions, interval builder and guided execution, race/event goals and tapering. Preserve deterministic metric calculations; coach language can narrate verified facts only. Add validation against known training fixtures and explain uncertainty.
9. **Social/safety:** real moderation/report/block/deletion operations, abuse workflows, club events and optionally messaging; privacy-by-default opt-in live location share (Beacon-like utility), gear/equipment mileage, weather context and group events. Deploy and operate workers before exposing sensitive social capabilities.
10. **Polish and release:** final screen-by-screen visual/accessibility review (safe areas, Dynamic Type, contrast, Reduce Transparency, light/dark, native bars), VoiceOver/TalkBack labels, crash reporting without sensitive payloads, performance/memory/battery profiling, offline/error/retry audit, app privacy/support/account deletion flows, security/dependency review, Android build/device testing, production Supabase deployment/migrations/RLS, signing and store submissions.

Use current official Strava feature/sport lists only as a moving product baseline; do not copy branding/assets, layouts, wording, proprietary algorithms or data.
